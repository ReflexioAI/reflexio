Reconcile the NEW playbooks against each other and the related EXISTING rows.

Rows include content, trigger, rationale, source span, and a call-local Evidence Group. Evidence
groups are derived from overlap in persisted source interactions; they are not database IDs.
Shared evidence is a strong duplicate/merge signal, but it is not sufficient when the lessons or
outcomes differ. Different evidence groups may still describe the same durable lesson.

{new_playbooks}

[Existing related playbooks]
{existing_playbooks}

## Decisions

Every NEW label must appear exactly once across all decisions.

- `unify`: the consumed NEW rows and any archived EXISTING positions support the same atomic
  lesson. List every consumed NEW label in `new_id`, preserve every supported constraint, and
  return final content/trigger/rationale. Merge only duplicates or the same decision rule; merely
  related lessons stay separate. Never let one candidate's unsupported clause borrow another
  candidate's evidence.
- `reject_new`: an EXISTING row already covers the candidate. Provide the EXISTING list position
  in `superseded_by_existing_id` and a concise reason.
- `differentiate`: both rules are valid but apply to mutually exclusive situation classes. Refine
  both triggers without using incidental later facts. Handles exactly one NEW row.
- `independent`: the candidate is a distinct supported lesson and should be inserted unchanged.

`archive_existing_ids`, `superseded_by_existing_id`, and `existing_id` contain bare EXISTING
list-position integers. `new_id` contains `NEW-N` labels and may be a list for unify,
reject_new, or independent.

## Hard constraints

- Cover every NEW label exactly once. Do not omit a NEW row whose facts were absorbed by a unify.
- Do not produce multiple survivors with overlapping evidence and substantially overlapping
  content; combine them or reject the redundant row.
- Do not unify same-situation contradictory advice.
- Preserve source-supported failure details, but remove speculative prevention, unsupported
  causality, generic restatements, and internal-success-as-user-value claims.
- Rewritten content may narrow or remove an unsupported clause, but it may not introduce a new
  instruction, prohibition, claimed outcome, fallback, or workflow step absent from the consumed
  rows and their evidence. In particular, do not add generic "do not claim success" or delivery
  precautions unless an observed false claim or non-delivery is in the shown evidence.
- Persisted rationale must explain the observed signal and future benefit in user-facing terms.
  Never mention NEW/EXISTING labels, evidence groups, consolidation, or the merge decision in it.
- Preserve concrete operational surfaces such as the actual artifact, target, check, or boundary;
  for example, retain target groups, SGs, health checks, task defs when the evidence supports
  those surfaces. Do not compress a supported fanout rule into a generic sweep/audit rule.
- Every rewritten trigger must be evaluable at the earliest future decision point. Later facts may
  `or`-broaden but never `and`-narrow it.
- Prefer focused separate rules over a bloated merge when the outcomes or applicability differ.

Return only a `PlaybookConsolidationOutput` JSON object with the `decisions` key. Do not add prose,
comments, markdown, or extra top-level keys.
