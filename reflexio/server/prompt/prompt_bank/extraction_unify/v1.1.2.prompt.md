You are reviewing extraction proposals from THREE parallel passes that examined the same conversation. Each pass focused on a different memory axis. Your job is to identify duplicates — both **cross-axis** (the same atom captured by two different passes) and **within-axis** (paraphrases or strict subsets in a single pass) — and drop the redundant version.

## Pass A — UserProfile (user-side facts and preferences)
{pass_a_ops}

## Pass B — UserProfileAgentRec (agent-named answers / recommendations the agent gave the user)
{pass_b_ops}

## Pass C — UserPlaybook (procedural rules / playbooks for the agent to follow)
{pass_c_ops}

## Rules

1. **Cross-axis dedup.** When the same atom appears in two passes, drop the weaker copy.
   - If Pass B captured an "agent recommendation" that is really just restating a Pass A user fact, drop the Pass B op.
   - If Pass A captured a fact that already covers the substance of a Pass C playbook trigger, drop only when the playbook adds NO operational guidance.

2. **Within-axis paraphrase dedup.** Two ops in the SAME pass that encode the same atom in different wording, with neither carrying a unique operand the other lacks. DROP the wordier or weaker phrasing. Example: `[0] CREATE profile: user enjoys reading mystery novels` and `[1] CREATE profile: user likes mystery books` — DROP `[1]`. The remaining op carries the atom forward; nothing is lost.

3. **Within-axis strict-subset dedup.** When one op's content is fully contained in another op that adds a unique operand or detail, the longer op dominates — DROP the shorter op (the subset). Nothing is lost because the longer op preserves both the shared atom AND the extra detail.
   - Example: `[0] CREATE profile: user runs three times a week` and `[1] CREATE profile: user runs three times a week, usually 5 km each session` — DROP `[0]`. `[1]` preserves the routine AND the per-session distance.
   - The richer op always wins; the subset is pure redundancy.

4. **Different facets / angles → KEEP BOTH** (do NOT apply rules 2 or 3).
   - Cross-axis facet example: Pass A "user told assistant they are vegan" + Pass B "agent recommended a vegan restaurant" — KEEP BOTH (one is the user's fact, the other is the agent's answer).
   - Within-axis facet example: `[0] user enjoys hiking` and `[1] user prefers solo hikes over group hikes` — KEEP BOTH (general preference vs. specific modality; neither is a subset of the other).
   - **Different unique operands → KEEP BOTH**: when each op carries a different unique operand the other lacks (e.g., `[0]` has the date, `[1]` has the price; or `[0]` has "a friend made", `[1]` has "ten years ago"), each is operand-rich along a different axis. Neither is a subset of the other. KEEP BOTH.

5. **Never drop ops that contain unique operands** (specific numbers, dates, names, prices, exact phrases, temporal qualifiers like "ten years ago", "last summer"). The operand-bearing op is always the survivor in any dedup decision; never drop it in favor of an operand-poor variant.

6. **Never drop DELETE ops.** They reflect storage-state reasoning the agent did during its loop.

7. **When in doubt, KEEP.** False-keeps are recoverable; false-drops permanently lose information. "In doubt" means you genuinely cannot tell whether two ops cover the same atom or whether they're different facets — NOT a hedge against applying the dedup rules when the relationship is clear.

## Output format

Reply with one decision per line, in the form:

```
DROP A.<index>
DROP B.<index>
DROP C.<index>
```

Within-axis drops use the same syntax — e.g., dropping a subset of another op in Pass A is `DROP A.<index of subset op>`.

If nothing should be dropped, reply with exactly: `KEEP ALL`

Use only the indices listed in the pass blocks above. Indices are 0-based and per-pass.
