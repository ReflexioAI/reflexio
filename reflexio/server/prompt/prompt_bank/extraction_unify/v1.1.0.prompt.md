You are reviewing extraction proposals from THREE parallel passes that examined the same conversation. Each pass focused on a different memory axis. Your job is to identify duplicates — both **cross-axis** (the same atom captured by two different passes) and **within-axis** (paraphrases of the same atom captured more than once in a single pass) — and drop the weaker version.

## Pass A — UserProfile (user-side facts and preferences)
{pass_a_ops}

## Pass B — UserProfileAgentRec (agent-named answers / recommendations the agent gave the user)
{pass_b_ops}

## Pass C — UserPlaybook (procedural rules / playbooks for the agent to follow)
{pass_c_ops}

## Rules

1. **Same atom captured twice → drop the weaker one.** This applies to two patterns:
   - **Cross-axis**: an atom appears once in Pass A and once in Pass B/C.
     - If Pass B captured an "agent recommendation" that is really just restating a Pass A user fact, drop the Pass B op.
     - If Pass A captured a fact that already covers the substance of a Pass C playbook trigger, drop only when the playbook adds NO operational guidance.
   - **Within-axis**: two ops in the SAME pass encode the same atom in different wording.
     - Example: `[0] CREATE profile: user enjoys reading mystery novels` and `[1] CREATE profile: user likes mystery books` — same atom, two phrasings. DROP the weaker one (the one with less specific or fewer load-bearing words). The remaining op carries the atom forward; nothing is lost.
     - Subset relation also counts: if `[0]` says everything `[1]` says plus more, drop `[1]`.
2. **Different facets / angles on the same topic are NOT duplicates.** Keep both.
   - Cross-axis example: Pass A "user told assistant they are vegan" + Pass B "agent recommended a vegan restaurant" — KEEP BOTH (one is the user's fact, the other is the agent's answer).
   - Within-axis example: `[0] user enjoys hiking` and `[1] user prefers solo hikes over group hikes` — same topic, different facets (general preference vs. specific modality). KEEP BOTH.
3. **Never drop DELETE ops.** They reflect storage-state reasoning the agent did during its loop.
4. **Never drop ops that contain unique operands** (specific numbers, dates, names, prices, exact phrases, temporal qualifiers like "ten years ago", "last summer"). Those are the answer-bearing details and must survive — even when two ops look like paraphrases, if one carries a unique operand the other lacks, KEEP the one with the operand. Prefer to keep BOTH if uncertain which is the operand-richer version.
5. **When in doubt, KEEP.** False-keeps are recoverable; false-drops permanently lose information.

## Output format

Reply with one decision per line, in the form:

```
DROP A.<index>
DROP B.<index>
DROP C.<index>
```

Within-axis drops use the same syntax — e.g., dropping the second of two paraphrases in Pass A is `DROP A.<index of weaker op>`.

If nothing should be dropped, reply with exactly: `KEEP ALL`

Use only the indices listed in the pass blocks above. Indices are 0-based and per-pass.
