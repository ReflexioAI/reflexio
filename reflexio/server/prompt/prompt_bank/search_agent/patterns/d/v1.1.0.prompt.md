### Pattern D — Counting / aggregation of distinct atoms (REHYDRATE-FIRST)
Structure: a complete answer enumerates ≥2 distinct items of the same type, OR is a count / sum / superlative across many candidates. The answer-noun is plural ("books", "games", "items", "trips", "people"), or the question contains a counting/aggregation operator ("how many", "total", "list all", "which X did I do the most/least"). Surface phrasing varies — use the structural test, not phrase matching.

**Architectural framing for Pattern D (READ THIS FIRST).** Profiles are POINTERS, not the answer. They name the topic and carry a `session_id` that points to the source conversation. The actual list members (book titles, place names, sport names) live in the raw turns of those sessions; profile compression collapsed them into summary atoms. Your job in Pattern D is NOT to extract the answer from profiles — it's to find the right session_ids and rehydrate. Treat profiles as the INDEX; treat raw turns as the EVIDENCE.

Recipe (rehydrate-first; minimal agent discretion):
1. `search_user_profiles(query verbatim, top_k=10)` — small first pass, just to surface the relevant `session_id`s. Topic match is sufficient; you do NOT need the profile to contain the specific answer items. A profile that says `user is into fantasy literature` is a valid pointer for "Which books has user read?" — its session_id is the index entry.
2. **UNCONDITIONAL rehydration** (no judgment step): collect the distinct `session_id`s from step 1's top hits and call `read_session_text(session_ids=[<top 4 distinct>])` in a single call. **Do not decide whether to rehydrate — always rehydrate for Pattern D.** Skipping rehydration is a workflow violation regardless of how confident you feel about step 1's results.
3. **Apply the question's qualifier strictly to the raw turns** (not to profiles). If the question says `besides X`, drop instances matching X; if `not Y`, drop Y-related; if `during Z`, keep only instances whose context mentions Z.
4. **Enumerate the surviving instances from the raw turns** + any profile-content instances. Dedupe by real-world entity. Finish.

**The only valid Pattern D bypass.** Skip step 2 ONLY when step 1's top_k=10 returns ZERO profiles whose content names the question's topic (e.g. zero food-related profiles when asking "what foods has user mentioned"). When the topic is absent from memory entirely, rehydration is wasted. Every other case — including when step 1 surfaces topic-naming profiles that don't seem to contain the specific answer items — rehydration is mandatory.

**Why rehydrate-first.** Multi_hop list questions chronically fail in this system because:
1. Profile compression drops list items not prominently named in their source turn.
2. The agent searches multiple times trying to find the items in profile content, doesn't find them, finishes with what it has.
3. The right items were always in the raw turns; the agent never read them.

Forcing unconditional rehydration removes the agent's ability to bypass the step that finds the actual answer. Yes, it costs one extra LLM call per Pattern D question (~$0.002, 8 KB tokens). That cost is justified: the "skip rehydration when I think I have enough" path has empirically been the dominant multi_hop failure mode.

Reasoning hint: Count only atoms satisfying every predicate. Separate candidates into qualifies, related-but-not-qualifying, duplicate, and superseded. Dedupe by real-world item/project/event, not profile id. For action/status questions, require the action/status words in the evidence (pickup/return, led/currently leading), not merely membership in the broad category. If the predicate contains alternatives ("pick up or return", "led or currently leading"), count atoms satisfying either branch, but do not infer a branch from unrelated context.
Rerank: prefer `rerank=False` on the small first pass — you only need topic match to find session_ids, not fine-grained ranking. **Exception — branded-category questions** (e.g. "which grocery store did I spend most at", "list all my streaming subscriptions", "how many luxury items did I buy"): when the question targets a CATEGORY whose answers are brand/proper-noun mentions that don't share the literal category keyword, set `llm_rerank=True` on the first pass so brand-mentioning profiles surface as session_id pointers. **The rehydration step is unconditional regardless of rerank choice.**
Rehydration use: UNCONDITIONAL per step 2. The only valid skip is the absent-topic case (zero topic-matching profiles).
